# V1.6.0 情侣衣橱（CHANGELOG 副本）

> 时间戳：2026-09-05 11:29 · 设计文档：[2026-09-05-couple-wardrobe-design.md](../superpowers/specs/2026-09-05-couple-wardrobe-design.md) · E2E：[verify-v160.cjs](../../../client/verify-v160.cjs) 13/13 全绿

## 1. 三机制合一的主题系统（client/src/live2d/couple.ts）

一张 `COUPLE_THEMES` 表驱动三种机制，服务端 [index.js](../../../server/src/index.js) 持有镜像配置：

- **A. 一键情侣装**：5 个纯色主题（海雾🌊/暮樱🌸/旷野🌲/暗夜🌌/经典黑白🖤）——`POST /api/couple-outfit` 服务端权威结算，按双方形象性别分发对应槽位（男取 `m` 槽、女取 `f` 槽，同性别双子装都取 `m` 槽），更新双方 `users.style/outfit` 后 `couple_applied` 双端推送
- **B. 情侣徽章**：`matchCoupleTheme` 纯客户端匹配，双方 style/outfit 命中同一主题即点亮 `✨` 徽章，服务端零新列
- **C. 成套款式**：2 个同图案情侣针织（海雾格纹🧵 = Chitose `knit_sea` × Haru `sailor_sea`；暮樱爱心🩷 = `knit_heart` × `sailor_heart`）——gen-outfit-variants.mjs 程序化叠加格纹/心形曲线图案，WebP+SD LOD 四件套全量生成，替换区外零改动校验通过
- **解除**：`none` 主题双端回 原生+base，徽章熄灭

## 2. 客户端（App.tsx / api.ts / styles.css）

- 衣橱新增「情侣装」行（有 partner 才渲染）：双色渐变 chip ×8（7 主题+解除），当前生效主题高亮
- `applyCoupleTheme`：本地乐观更新 + REST 结算 + `couple_applied` 回声 `_applied` 判重幂等（发起端免二次重载）
- 接收端免操作自动应用：`couple_applied` → 自己走 `applyCoupleMemberSelf`，对方走 `swapPartnerLook`，toast「TA 给你换上了…」
- 徽章点亮瞬间双人头顶冒心（同主题只触发一次）
- **离线愈合**：启动/重连时 `getState` 对比服务端与本地 style/outfit，差异即拉齐并热更新分身（TA 在你离线时给你换了情侣装也能自动穿上）
- UI 细节：`styles.css` 新增 `.couple-row/.couple-chip/.couple-dot/.couple-badge`

## 3. 稳定性修复

- **徽章优先级**：`matchCoupleTheme` 原按表序匹配，`seafog` 与 `seafog-plaid` 的 style 槽相同（navy/ocean），应用成套款后徽章会误亮纯色主题 → 改为成套款（OUTFIT_COUPLE_SETS）优先匹配，chip 高亮随之正确
- **上游竞态补丁**（pixi-setup.ts）：pixi-live2d-display 0.4.0 `ExpressionManager.loadExpression` 在模型 swap 销毁后 resolve 时对被 `destroy()` 清空的 `this.expressions` 赋值 → unhandled rejection（`Cannot set properties of undefined (setting '4')`）。补丁仅在「已销毁」时静默吞掉该 rejection，其他错误照常抛出
