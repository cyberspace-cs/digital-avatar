## 一、问题诊断

### 1.1 当前渲染问题

用户反馈：Jing/Tao 序列帧渲染出来有很多白边，效果不行。

### 1.2 白边根因分析（已确认）

| 根因 | 说明 | 影响程度 |
|------|------|----------|
| **PIXI 线性过滤** | `SpriteAvatar` 加载纹理时未设置 `scaleMode = NEAREST`，GPU 默认 LINEAR 双线性插值，缩放时把边缘半透明白色像素与透明区域混合 | 🔴 高 |
| **未开启 roundPixels** | PIXI Application 未设置 `roundPixels: true`，精灵位置未对齐像素网格，亚像素渲染导致边缘模糊 | 🟡 中 |
| **去底羽化边缘** | `remove-background.py` 对 alpha 通道做了 GaussianBlur(radius=1.0)，边缘产生半透明白色像素（RGB=255, Alpha=64~200），LINEAR 下放大白边 | 🟡 中 |
| **帧间边缘不一致** | 每帧独立去底，边缘腐蚀/羽化参数相同但内容不同，序列播放时边缘微抖 | 🟢 低 |

### 1.3 序列帧的固有局限

- 动作数量有限（当前仅 wave/heart 各5帧）
- 无参数驱动能力（不能眼球跟踪、实时表情、嘴型同步）
- idle 仅靠程序呼吸微动效，灵动感不足
- 文件体积随动作数线性增长

## 二、QQ秀底层技术调研结论

### 2.1 QQ秀的本质：纸娃娃系统（Paper Doll System）

经多源调研（CSDN、人人都是产品经理、掘金、专利文献），QQ秀的技术核心是：

1. **多层静态PNG叠加**：头部、发型、上衣、下装、配饰各一层，每层图片尺寸相同，透明背景，通过 z-index 控制叠放顺序
2. **换装=换层**：切换装扮只需替换对应层的图片，其他层不动
3. **动作=预渲染帧序列**：QQ秀的"动作"本质是提前画好的帧序列（闪动头像机制：2-10帧@4-10fps循环），不是实时骨骼动画
4. **早期用Flash矢量图**：2003-2012年QQ秀基于Flash，矢量图+分层元件；后期因手机性能问题转向静态图合成
5. **新版QQ秀（2026）**：AI驱动生成形象，虚幻引擎4渲染3D模型，但这是超重型方案

### 2.2 对本项目的启示

- QQ秀的"动作即素材包"思路与当前 sprite-sequence 方案一致，方向正确
- 但QQ秀的素材是**专业美术在透明画布上分层绘制**的，边缘天然干净，不存在去底白边问题
- 我们的素材是**AI生成的白底图后处理去底**，这是白边问题的根源
- 要达到QQ秀级别的边缘质量，必须从**资产生产流程**上解决，而不是仅靠后处理

## 三、Live2D 路线可行性分析

### 3.1 Live2D vs 序列帧对比

| 维度 | Live2D (Cubism) | 序列帧 (Sprite Sequence) |
|------|-----------------|------------------------|
| **边缘质量** | ✅ 矢量网格，无限缩放无白边 | ❌ 依赖去底质量，易有白边 |
| **灵动性** | ✅ 参数驱动：眼球跟踪、呼吸、表情、嘴型 | ❌ 仅预渲染动作，无实时交互 |
| **资源体积** | ✅ 一套分层素材+参数曲线，几MB | ❌ 每动作5-10帧PNG，动作多了体积大 |
| **交互能力** | ✅ 可跟随鼠标、触摸反应、物理摆动 | ❌ 固定动作播放 |
| **制作成本** | 🔴 高：PSD分层→Cubism绑定→物理→动作，每角色数小时到数天 | 🟢 低：AI生成+去底，每角色1小时 |
| **AI生成友好度** | 🔴 低：AI生成单层图无法直接用，需拆分层+手动绑定 | 🟢 高：直接生成即用 |
| **代码复杂度** | 🟡 中：pixi-live2d-display已集成，旧模型可用 | 🟢 低：纯纹理切换 |

### 3.2 AI图转Live2D的最新进展（2025-2026）

经调研（arXiv、HuggingFace、博客园、GMO），单图转Live2D的自动化流水线已有突破：

1. **See-Through**（Kaggle竞赛方案）：基于SDXL的LayerDiff 3D + 微调Marigold深度估计，可将单图拆成最多24层RGBA PSD
2. **SAM 2 + PS生成式补图**：语义分割各部件，扩散模型补全被遮挡区域
3. **Bunraku**（arXiv 2026）：分层扩散 + 内容感知三角网格 + 关键点位移场预测，端到端生成可编辑Live2D
4. **Cubism Editor 5.x 自动绑定**：导入PSD后可自动生成网格和基础变形器

**但仍需手动工作**：
- 分层质量不稳定，需手动清理边缘
- 物理设置（头发摆动、衣服晃动）需手动调参
- 动作制作（motion3.json）仍需手动关键帧
- 完全自动化尚未成熟（Tier 3: Not Yet）

### 3.3 本项目做Live2D的工作量评估

| 阶段 | 工作内容 | 预估时间 | 工具 |
|------|---------|---------|------|
| 1. 分层素材 | AI生成分层PSD（头发前后、眉毛、眼睛、嘴巴、身体、手臂） | 2-3天/角色 | See-Through / SAM2 + PS |
| 2. Cubism绑定 | 导入PSD、生成网格、设置变形器、参数绑定 | 1-2天/角色 | Live2D Cubism Editor |
| 3. 物理+动作 | 物理摆动设置、idle/wave/heart动作制作 | 1-2天/角色 | Cubism Editor + Physics |
| 4. 集成测试 | 替换运行时资产、验证渲染、调参 | 0.5天 | pixi-live2d-display |
| **合计** | | **4.5-7.5天/角色** | |

两个角色（Jing+Tao）约 **9-15人天**。

## 四、修改方案

### 方案A：短期修复序列帧（推荐立即执行，1-2天）

**目标**：消除白边，提升渲染质量，增加程序微动效弥补灵动性。

#### A1. 资产端修复

1. **边缘腐蚀（Erosion）**：在 `remove-background.py` 中增加 alpha 通道形态学腐蚀，收缩1-2像素，吃掉残留白边
2. **去边（Defringe）**：对半透明边缘像素，将RGB向角色内部颜色靠拢，消除白色混合
3. **关闭羽化或减小羽化半径**：GaussianBlur radius 从 1.0 降到 0.3 或关闭，减少半透明像素
4. **预乘alpha处理**：确保半透明像素的RGB已预乘（premultiplied），避免混合时白边
5. **统一边缘处理**：所有帧用相同参数批量处理，确保帧间边缘一致

#### A2. 代码端修复

1. **设置纹理过滤为NEAREST**：`SpriteAvatar.loadTexture()` 中设置 `baseTexture.scaleMode = PIXI.SCALE_MODES.NEAREST`
2. **开启 roundPixels**：PIXI Application 增加 `roundPixels: true`
3. **像素对齐**：Sprite 位置 `Math.round()`，避免亚像素渲染
4. **纹理预处理**：加载后对纹理做一次边缘收缩（可选，用canvas 2D预处理）

#### A3. 增加程序微动效（提升灵动感）

1. **眨眼**：idle 状态下随机间隔（3-6秒）播放2帧眨眼（可用程序缩放眼睛区域实现，或额外生成眨眼帧）
2. **轻微摇摆**：idle 时身体 ±1° 缓慢摇摆（正弦曲线）
3. **眼球微动**：idle 时眼球缓慢偏移（如果是分层图可实现，序列帧可用整体轻微偏移模拟）
4. **动作过渡**：动作播放前后加 200ms 淡入淡出，避免硬切

### 方案B：中期 Live2D 路线（9-15人天，需专业工具）

**目标**：达到专业级渲染质量和交互灵动性。

#### B1. 资产端

1. 用 See-Through / SAM2 对 Jing/Tao 基准立绘做分层拆分
2. PS 手动清理分层边缘，补全被遮挡区域
3. 导出分层 PSD（至少：头发后、眉毛、眼睛、瞳孔、嘴巴、身体、手臂前、头发前）
4. Cubism Editor 导入 PSD，生成网格，设置变形器
5. 绑定参数：角度X/Y、呼吸、眨眼、表情、动作
6. 物理设置：头发摆动、衣服晃动
7. 制作动作：idle、wave、heart（.motion3.json）
8. 导出 .model3.json + 运行时资产

#### B2. 代码端

1. 现有代码已支持 Live2D（`pixi-live2d-display`，旧模型 hiyori/haru 就是 Live2D）
2. 只需替换 `client/public/models/jing/` 和 `tao/` 下的资产为 Cubism 标准结构
3. `models.ts` 中移除 `engine: 'sprite-sequence'` 标记，回退默认 legacy-pixi 渲染
4. 动作映射：Cubism motion 名称与 actionId 对应（idle/wave/heart）
5. 保留 sprite-sequence 作为降级方案（Live2D加载失败时回退）

### 方案C：混合方案（推荐长期路线）

- **基础形象**：Live2D（idle、呼吸、眨眼、眼球跟踪、物理摆动）
- **复杂动作**：序列帧（wave/heart 等大动作，Live2D 难做的大幅度动作）
- **切换机制**：idle 用 Live2D，触发动作时切换到序列帧播放，播完回 Live2D idle
- **优势**：兼顾灵动性和动作丰富度，降低 Live2D 动作制作成本

## 六、风险与注意事项

1. **契约红线**：不得删除旧模型（hiyori/haru/natori/chitose），Live2D 路线是新增而非替换
2. **降级链**：Live2D 加载失败必须能回退到序列帧或旧模型，不能白屏
3. **资产版权**：AI 生成的角色做 Live2D 需确认无版权问题
4. **工具成本**：Live2D Cubism Editor 免费版有导出限制（.model3.json 可导出，.moc3 有免费版标识），PRO版需付费
5. **性能**：Live2D 在低端设备上可能比序列帧更耗GPU，PerfGovernor 需适配
